# Hector MVP — Plan 2 of 4: Phase 10 Backend Enhancements

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** Implement all Phase 10 tickets (T-1000…T-1008) behind the API: email infrastructure + notifications, photo upload, geo proximity matching, request auto-expiry, password reset.

**Architecture:** New `services/` modules (email, photos, geo, expiry) consumed by existing routers; two new tables (`email_log`, `password_reset_tokens`); `users` gains optional lat/lng. APScheduler runs in-process. Default email transport is log-mode (console + DB) so everything is testable without SMTP.

**Tech Stack:** adds `aiosmtplib`, `pillow`, `apscheduler`. Existing FastAPI/SQLAlchemy/pytest stack unchanged.

**Spec:** `docs/superpowers/specs/2026-08-22-hector-mvp-design.md` §WS4 (decisions D5–D8).

## Global Constraints

Same as Plan 1 (branch, venv, gates). Additional:
- Emails never block the HTTP response path on failures; failures recorded in `email_log.status`.
- `POST /auth/forgot-password` returns 200 regardless of account existence (no enumeration).
- Reset tokens stored hashed (SHA-256), single-use, 1 h expiry.
- Photos: JPEG/PNG only, ≤5 MB, ≤2000×2000 px, stored under `media/dogs/{dog_id}/`, 400 px thumbnail generated; old files replaced.
- Geo: SQL bounding-box prefilter, Python-side Haversine on bounded set; missing coordinates exclude rows from distance sort rather than erroring.

- Tests: compatible owner notified once/day-cap respected; incompatible/not-available owner not emailed

### Task D4: Response notification to clinic (T-1003)
- Modify: respond endpoint sends clinic-staff email on ACCEPTED only
- Tests: accepted → one email logged to clinic email; declined → none

### Task D5: Photo upload (T-1001)
- Create: `services/photos.py` (validate type/size/pixels, save original+400px thumb, replace-old)

### Task D6: Owner location + geo matching (T-1004)
- Modify: `PATCH /auth/me` (new) accepting optional latitude/longitude; `GET /requests` accepts `lat`,`lng`,`max_distance_km` → distance_km field + sort asc, bounding-box prefilter

### Task D7: Request expiry job (T-1005)
- Create: `jobs/expire_requests.py` (`async def expire_overdue_requests(db) -> int`)
- Wire APScheduler in app lifespan (daily 00:05 UTC + startup sweep), guarded idempotent UPDATE ... WHERE status=OPEN AND needed_by_date < now
- Notify clinic staff via email service per expired batch
- Tests: sweep flips overdue rows only; scheduler wiring smoke-tested via lifespan startup flag

### Task D8: Password reset (T-1008)
- Schemas: ForgotPasswordRequest, ResetPasswordRequest
- Endpoints: `POST /auth/forgot-password` (always 200), `POST /auth/reset-password`
- Token: secrets.token_urlsafe(32), SHA-256 stored, expires_at = now+1h, used_at marks consumption
- Tests: forgot logs email w/ token link; reset works once; second use fails; weak passwords rejected; unknown email still 200
